# qual_by_position.py 사용 설명서

> FASTQ 파일에서 **read 안의 위치(몇 번째 염기인지)별 평균 품질 점수**를 계산하는 프로그램입니다.
> 이 문서는 프로그래밍과 시퀀싱 데이터를 처음 접하는 사람도 따라올 수 있도록 작성했습니다.

---

## 1. 프로그램의 목적

시퀀싱 기계는 DNA 조각(read)을 앞에서부터 한 염기씩 읽습니다.
그런데 읽어 나갈수록 화학 반응이 조금씩 흐트러져서, **read의 뒤쪽으로 갈수록 품질이 떨어지는 경향**이 있습니다.

`qual_by_position.py`는 이 경향을 숫자로 확인하기 위한 프로그램입니다.

- 모든 read의 **1번째 염기 품질**을 모아 평균을 내고,
- 모든 read의 **2번째 염기 품질**을 모아 평균을 내고,
- … 이것을 read의 마지막 위치까지 반복합니다.

결과를 보면 "몇 번째 염기부터 품질이 나빠지는지"를 알 수 있고,
이는 **trimming(품질 낮은 끝부분 잘라내기)을 어디서 할지** 정하는 근거가 됩니다.
FastQC 보고서의 *Per base sequence quality* 그래프가 보여 주는 것과 같은 정보를 직접 계산해 보는 것입니다.

## 2. FASTQ 파일의 구조

FASTQ 파일은 **read 하나가 항상 4줄**로 이루어져 있습니다.

```
@SRR1553607.1 1 length=101          ← 1번째 줄: '@' + read 이름
GTTAGCGTTGTTGATCGCGACGCAACAACTGG... ← 2번째 줄: 염기서열
+SRR1553607.1 1 length=101          ← 3번째 줄: '+' (구분용 줄)
BB@FFFFFHHHHHJJJJJJJJJJJJJJJJJJ... ← 4번째 줄: 품질 문자열
```

| 줄 | 내용 | 설명 |
|---|---|---|
| 1 | `@이름` | read를 구별하는 이름. 반드시 `@`로 시작 |
| 2 | 서열 | A, C, G, T(가끔 N)로 된 염기서열 |
| 3 | `+` | 서열과 품질을 구분하는 줄. 뒤에 이름이 다시 붙기도 함 |
| 4 | 품질 문자열 | **서열의 염기 하나마다 문자 하나**. 그래서 2번째 줄과 길이가 같음 |

### 품질 문자는 어떻게 숫자가 되나? (Phred+33)

품질 점수는 숫자 그대로 저장하지 않고, **점수에 33을 더한 값을 ASCII 문자로** 저장합니다.
따라서 문자의 ASCII 코드에서 33을 빼면 원래 점수가 됩니다.

| 문자 | ASCII 코드 (`ord`) | 품질 점수 (코드 − 33) |
|---|---|---|
| `#` | 35 | 2 |
| `5` | 53 | 20 |
| `?` | 63 | 30 |
| `I` | 73 | 40 |

품질 점수 Q는 그 염기가 **틀렸을 확률**을 나타냅니다. (Q = −10 × log₁₀(오류 확률))

| Q | 오류 확률 | 정확도 |
|---|---|---|
| 10 | 1/10 | 90% |
| 20 | 1/100 | 99% |
| 30 | 1/1,000 | 99.9% |
| 40 | 1/10,000 | 99.99% |

보통 **Q30 이상이면 매우 좋음, Q20 미만이면 주의**가 필요하다고 봅니다.

## 3. 위치별 평균 품질이란?

read 3개가 있고, 각 read의 품질 점수가 아래와 같다고 해 봅시다.

```
위치:     1   2   3   4   5
read A:  30  32  35  28  20
read B:  32  34  36  30  22
read C:  31  33  34  26  —     ← read C는 길이가 4
```

**위치별 평균 품질**은 *세로 방향*으로 평균을 내는 것입니다.

| 위치 | 계산 | 평균 |
|---|---|---|
| 1 | (30 + 32 + 31) / 3 | 31.00 |
| 2 | (32 + 34 + 33) / 3 | 33.00 |
| 3 | (35 + 36 + 34) / 3 | 35.00 |
| 4 | (28 + 30 + 26) / 3 | 28.00 |
| 5 | (20 + 22) / **2** | 21.00 |

여기서 중요한 점은 **5번 위치는 3이 아니라 2로 나눈다**는 것입니다.
read C에는 5번째 염기가 없기 때문입니다. trimming을 거친 FASTQ 파일처럼 read 길이가 서로 다를 때
이렇게 "그 위치에 실제로 염기가 있는 read 수"로 나누어야 올바른 평균이 나옵니다.

> 참고: read 하나의 평균(가로 방향)을 구하는 것은 *read별 평균 품질*이고,
> 이 프로그램이 구하는 것은 *위치별 평균 품질*(세로 방향)입니다. 둘을 혼동하지 마세요.

## 4. 코드의 주요 부분과 반복문의 역할

프로그램은 함수 3개와 메인 실행 부분으로 나뉩니다.

```
read_fastq()               → FASTQ 파일을 읽어 read 목록을 만든다
qual_to_scores()           → 품질 문자열을 숫자 점수 목록으로 바꾼다
mean_quality_by_position() → 위치별 평균을 계산한다
메인 실행 부분              → 위 함수들을 차례로 호출하고 결과를 출력한다
```

### 4-1. `read_fastq(filename)` — 파일 읽기

```python
with open(filename) as f:
    lines = f.readlines()

for i in range(0, len(lines), 4):
    name = lines[i].rstrip()[1:]   # 맨 앞의 '@'를 떼어낸다.
    seq = lines[i + 1].rstrip()
    qual = lines[i + 3].rstrip()
    records.append((name, seq, qual))
```

- `f.readlines()`로 파일의 모든 줄을 리스트에 담습니다.
- **반복문 `range(0, len(lines), 4)`** 는 i를 0, 4, 8, 12, … 처럼 **4씩 건너뛰며** 증가시킵니다.
  FASTQ는 read 하나가 4줄이므로, i는 항상 각 read의 첫 줄(`@이름`)을 가리킵니다.
  - `lines[i]` → 이름 줄, `lines[i+1]` → 서열, `lines[i+3]` → 품질 (`lines[i+2]`인 `+` 줄은 쓰지 않음)
- `rstrip()`은 줄 끝의 줄바꿈 문자(`\n`)를 지웁니다. `[1:]`은 첫 글자 `@`를 떼어 냅니다.
- 결과는 `(이름, 서열, 품질문자열)` 튜플의 리스트입니다.

### 4-2. `qual_to_scores(qual)` — 문자를 점수로

```python
for ch in qual:
    scores.append(ord(ch) - 33)
```

- **반복문 `for ch in qual`** 은 품질 문자열의 문자를 하나씩 꺼냅니다.
- `ord(ch)`는 문자의 ASCII 코드를 돌려줍니다. 여기서 33을 빼면 Phred 점수가 됩니다.
- 예: `"II#"` → `[40, 40, 2]`

### 4-3. `mean_quality_by_position(reads)` — 핵심 계산

이 함수는 위치마다 두 개의 값을 기록합니다.

- `totals[i]` : i번째 위치 품질 점수의 **합계**
- `counts[i]` : i번째 위치에 염기가 있는 **read의 개수**

```python
for name, seq, qual in reads:              # ① 바깥 반복문: read 하나씩
    scores = qual_to_scores(qual)

    for i, score in enumerate(scores):     # ② 안쪽 반복문: 그 read의 위치 하나씩
        if i >= len(totals):               # ③ 처음 보는 위치면 칸을 새로 만든다
            totals.append(0)
            counts.append(0)

        totals[i] += score
        counts[i] += 1
```

**① 바깥 반복문** — 파일의 모든 read를 처음부터 끝까지 하나씩 처리합니다.

**② 안쪽 반복문** — 현재 read의 품질 점수를 위치 순서대로 하나씩 처리합니다.
`enumerate`는 `(위치 번호, 값)`을 함께 줍니다. 위치 번호는 **0부터** 시작합니다.

```python
for i, score in enumerate([30, 32, 35]):
    # i=0, score=30
    # i=1, score=32
    # i=2, score=35
```

**③ 리스트 늘리기** — 처음에는 `totals`와 `counts`가 빈 리스트입니다.
지금까지 본 것보다 긴 read가 나오면, 새 위치를 위해 0을 하나씩 추가합니다.
그래서 **read 길이를 미리 몰라도**, 길이가 제각각이어도 동작합니다.

앞의 3장 예시로 따라가 보면:

| 처리한 read | totals | counts |
|---|---|---|
| (시작) | `[]` | `[]` |
| A (30,32,35,28,20) | `[30, 32, 35, 28, 20]` | `[1, 1, 1, 1, 1]` |
| B (32,34,36,30,22) | `[62, 66, 71, 58, 42]` | `[2, 2, 2, 2, 2]` |
| C (31,33,34,26) | `[93, 99, 105, 84, 42]` | `[3, 3, 3, 3, 2]` |

마지막으로 **세 번째 반복문**이 위치마다 `합계 / 개수`를 계산합니다.

```python
for i in range(len(totals)):
    means.append(totals[i] / counts[i])
# → [31.0, 33.0, 35.0, 28.0, 21.0]
```

### 4-4. 메인 실행 부분

```python
if len(sys.argv) < 2:
    print("사용법: python qual_by_position.py <FASTQ 파일>", file=sys.stderr)
    sys.exit(1)

reads = read_fastq(sys.argv[1])
means = mean_quality_by_position(reads)

for i, mean in enumerate(means):
    print(f"{i + 1}\t{mean:.2f}")
```

- `sys.argv`는 명령어에 적은 단어들의 리스트입니다.
  `python src/qual_by_position.py data/x.fastq`라면 `sys.argv[1]`이 `data/x.fastq`입니다.
  파일 이름을 안 적으면 사용법을 알려 주고 종료합니다.
- **마지막 반복문**은 결과를 한 줄씩 출력합니다. 파이썬 인덱스는 0부터지만
  사람에게는 1번 위치부터가 자연스러우므로 `i + 1`로 출력합니다.
- `{mean:.2f}`는 소수점 아래 둘째 자리까지 표시하라는 뜻이고, `\t`는 탭 문자입니다.

## 6. 실행 결과 해석

### 출력 형식

```
위치<TAB>평균품질
```

`data/SRR1553607_1.fastq`(read 203,445개, 길이 101)로 실행한 실제 결과 중 일부입니다.

```
1	32.04
2	32.17
3	32.28
4	35.85
5	35.65
...
25	37.97
...
50	33.44
...
75	30.63
...
100	28.93
```

출력은 모두 **101줄**(read 길이 101)입니다.

### 읽는 방법

| 구간 | 평균 품질 | 해석 |
|---|---|---|
| 1~3번 | 약 32 | read 맨 앞은 기계가 신호를 맞추는 구간이라 약간 낮은 경우가 많음 |
| 4~25번 근처 | 약 36~38 | 가장 품질이 좋은 구간 |
| 50번 | 33.44 | 서서히 낮아지기 시작 |
| 75번 | 30.63 | Q30 근처까지 감소 |
| 100번 | 28.93 | Q30 아래로 떨어짐 |

이 데이터는 **뒤로 갈수록 품질이 서서히 떨어지는 전형적인 Illumina 패턴**을 보입니다.
평균이 끝까지 Q20보다 높으므로 전체적으로 나쁜 데이터는 아니지만,
Q30 아래로 내려가는 **read 끝부분(대략 80번 위치 이후)은 trimming을 고려**해 볼 수 있습니다.

### 해석할 때 주의할 점

- **평균은 낮은 값을 가립니다.** 위치별 평균이 30이어도 그 위치에 Q2인 read가 섞여 있을 수 있습니다.
  FastQC 그래프의 상자(사분위수)도 함께 보면 분포를 더 잘 알 수 있습니다.
- **trimming된 파일은 뒤쪽 위치의 read 수가 적습니다.** 예를 들어 100번 위치의 평균이
  소수의 read로만 계산되었을 수 있습니다. 이 프로그램은 위치별 read 수(`counts`)를 출력하지 않으므로 이 점을 기억해 두세요.
- **Phred+33 방식을 가정합니다.** 매우 오래된 Illumina 데이터(Phred+64)에 사용하면 점수가 31씩 높게 나옵니다.
- **파일 전체를 메모리에 올립니다.** 수 GB 크기의 FASTQ에서는 메모리가 부족할 수 있습니다.
- FASTQ가 **read당 정확히 4줄**이라고 가정합니다. 서열이 여러 줄로 나뉜 파일은 올바르게 읽지 못합니다.
