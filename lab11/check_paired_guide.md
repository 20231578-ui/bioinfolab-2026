# check_paired.py 사용 설명서

> paired-end FASTQ 파일 두 개(`_1`, `_2`)가 **올바르게 짝을 이루는지** 확인하는 프로그램입니다.
> 이 문서는 프로그래밍과 시퀀싱 데이터를 처음 접하는 사람도 따라올 수 있도록 작성했습니다.

---

## 1. Paired-end sequencing이란?

시퀀싱을 하려면 먼저 긴 DNA를 수백 bp 정도의 작은 조각(**fragment**)으로 자릅니다.
그런데 시퀀싱 기계는 한 번에 조각 전체를 읽지 못하고, 끝에서부터 100~150염기 정도만 읽을 수 있습니다.

- **Single-end sequencing**: 조각의 **한쪽 끝만** 읽습니다.
- **Paired-end sequencing**: 같은 조각을 **양쪽 끝에서 한 번씩**, 총 두 번 읽습니다.

```
                 DNA 조각 (fragment, 예: 약 300 bp)
   5' ==================================================== 3'
   3' ==================================================== 5'

      R1 ───────────>                                        (앞쪽 끝에서 읽음)
                                      <─────────── R2        (반대쪽 끝에서 읽음)
```

이렇게 한 조각에서 나온 두 read를 **짝(pair, mate)** 이라고 부릅니다.

Paired-end가 좋은 이유:

- 두 read가 **같은 조각에서 왔고 거리가 대략 정해져 있다**는 정보가 생깁니다.
- 그래서 유전체에 read를 붙일 때(mapping) 반복 서열 같은 애매한 곳에서도 위치를 더 정확히 찾을 수 있습니다.
- 삽입·결실·구조 변이 같은 큰 변화를 찾는 데에도 도움이 됩니다.

---

## 2. R1과 R2 FASTQ 파일의 차이

Paired-end 결과는 보통 **파일 두 개**로 나뉘어 저장됩니다.

| 파일 | 다른 이름 | 내용 |
|------|-----------|------|
| `SRR1553607_1.fastq` | R1, read 1, forward | 각 조각의 **첫 번째** read |
| `SRR1553607_2.fastq` | R2, read 2, reverse | 각 조각의 **두 번째** read (반대쪽 끝) |

가장 중요한 규칙은 다음 두 가지입니다.

1. **두 파일의 read 개수가 같아야 합니다.** (조각 하나당 R1 하나, R2 하나)
2. **같은 순서에 있는 read끼리 짝입니다.** R1 파일의 *n*번째 read와 R2 파일의 *n*번째 read는 같은 조각에서 나온 것이어야 합니다.

> R2는 반대쪽 가닥에서 읽은 것이므로, R2의 서열은 R1과 **다릅니다.**
> 그래서 짝을 확인할 때 서열은 비교하지 않고 **이름**을 비교합니다.

이 규칙이 깨지는 경우의 예:

- 한쪽 파일만 trimming/필터링해서 일부 read가 빠졌을 때
- 다운로드나 복사가 중간에 끊겨 한쪽 파일이 잘렸을 때
- 서로 다른 샘플의 파일을 실수로 짝지었을 때

이런 상태로 mapping 프로그램(BWA, Bowtie2 등)에 넣으면 오류가 나거나, 더 나쁘게는 **오류 없이 틀린 결과**가 나옵니다.
그래서 분석 전에 짝이 맞는지 확인하는 것이 중요합니다.

## 3. FASTQ 파일의 기본 구조

FASTQ 파일은 **read 하나가 항상 4줄**로 이루어져 있습니다.

```
@SRR1553607.1 1 length=101          ← 1번째 줄: '@' + read 이름
GTTAGCGTTGTTGATCGCGACGCAACAAC...    ← 2번째 줄: 염기서열
+SRR1553607.1 1 length=101          ← 3번째 줄: '+' (구분용 줄, 이름이 반복되기도 함)
BB@FFFFFHHHHHJJJJJJJJJJJJJJJJ...    ← 4번째 줄: 품질 문자열 (염기 하나당 문자 하나)
@SRR1553607.2 2 length=101          ← 다음 read의 1번째 줄
...
```

줄 번호를 0부터 세면, read 이름 줄은 0, 4, 8, 12, … 번째 줄입니다.
즉 **줄 번호를 4로 나눈 나머지가 0인 줄**이 이름 줄입니다. 이 프로그램은 이 규칙을 이용합니다.

> 품질 문자열에도 `@` 문자가 나올 수 있으므로(위 예시의 `BB@FF...`),
> "`@`로 시작하는 줄 = 이름 줄"이라고 판단하면 틀릴 수 있습니다. 줄 번호로 판단하는 것이 안전합니다.

---

## 4. 왜 read 이름을 비교하나요?

같은 조각에서 나온 R1과 R2는 시퀀싱 기계가 **같은 이름(ID)** 을 붙여 줍니다.
실제 데이터를 보면:

```
SRR1553607_1.fastq 의 첫 read:  @SRR1553607.1 1 length=101
SRR1553607_2.fastq 의 첫 read:  @SRR1553607.1 1 length=101
```

두 파일의 첫 번째 read 이름이 같습니다 → 짝이 맞습니다.

- 서열은 R1과 R2가 원래 다르므로 비교 기준이 될 수 없습니다.
- 이름은 짝끼리 같도록 만들어져 있으므로, **같은 위치의 이름이 같은지**만 보면 짝이 맞는지 알 수 있습니다.

---

## 5. `/1`, `/2` 와 Illumina read 이름 형식

짝끼리 이름이 "같다"고 했지만, 실제로는 **몇 번째 mate인지 표시하는 부분**이 붙어서 조금 다를 수 있습니다.
이 부분은 R1과 R2에서 원래 다르므로, 비교할 때는 떼어 내야 합니다.

### (1) 예전 Illumina 형식 (`/1`, `/2`)

```
R1: @HWUSI-EAS100R:6:73:941:1973#0/1
R2: @HWUSI-EAS100R:6:73:941:1973#0/2
```

이름 맨 끝의 `/1`은 R1, `/2`는 R2라는 뜻입니다. 이것을 떼면 두 이름이 같아집니다.

### (2) 최신 Illumina 형식 (Casava 1.8 이후)

```
R1: @M00123:5:000000000-A1B2C:1:1101:15589:1331 1:N:0:1
R2: @M00123:5:000000000-A1B2C:1:1101:15589:1331 2:N:0:1
```

공백을 기준으로 앞부분과 뒷부분으로 나뉩니다.

- **공백 앞**: read의 실제 ID — `기계이름:run번호:flowcell ID:lane:tile:x좌표:y좌표`
  (flowcell 위에서 이 DNA 조각이 있던 **위치**이므로, R1과 R2가 같습니다.)
- **공백 뒤**: 부가 정보 — `mate번호:필터여부:control번호:index`
  - 첫 숫자 `1` 또는 `2`가 R1/R2 구분입니다.
  - `N`은 품질 필터를 통과했다는 뜻(`Y`면 걸러진 read)입니다.

### (3) SRA에서 받은 형식 (이번 실습 데이터)

```
R1: @SRR1553607.1 1 length=101
R2: @SRR1553607.1 1 length=101
```

`SRR1553607.1`이 ID이고, 뒤의 `1 length=101`은 "1번 spot, 길이 101"이라는 부가 정보입니다.

### 정리: 비교 규칙

세 형식 모두 다음 두 단계를 거치면 짝끼리 같은 "기본 이름"이 됩니다.

1. **공백 앞부분만 남긴다.** → `1:N:0:1`, `2:N:0:1`, `1 length=101` 같은 정보가 사라짐
2. **끝이 `/1`이나 `/2`이면 잘라낸다.**

| 원래 이름 | 기본 이름 |
|-----------|-----------|
| `SRR1553607.1 1 length=101` | `SRR1553607.1` |
| `read123/1` | `read123` |
| `M00123:5:000:1:1101:15589:1331 1:N:0:1` | `M00123:5:000:1:1101:15589:1331` |

## 6. 코드 설명

프로그램은 함수 3개로 이루어져 있습니다.

| 함수 | 하는 일 |
|------|---------|
| `read_fastq_names(filename)` | FASTQ 파일에서 read 이름만 모아 리스트로 돌려줌 |
| `base_name(full_name)` | 이름에서 mate 표시를 떼고 기본 이름을 돌려줌 |
| `main()` | 두 파일을 읽고, 개수와 이름을 비교하고, 결과를 출력함 |

### 6-1. `read_fastq_names` — 이름만 모으기

```python
names = []
with open(filename) as f:
    for line_no, line in enumerate(f):
        if line_no % 4 == 0:
            line = line.rstrip()
            if line == "":
                continue
            names.append(line[1:])
return names
```

- `with open(filename) as f:` 파일을 열고, 블록이 끝나면 자동으로 닫습니다.
- `for line_no, line in enumerate(f):` 파일을 **한 줄씩** 읽는 반복문입니다.
  `enumerate`는 줄 내용(`line`)과 함께 줄 번호(`line_no`, 0부터 시작)를 줍니다.
- `if line_no % 4 == 0:` 줄 번호를 4로 나눈 나머지가 0이면 이름 줄입니다(3장 참고).
- `line.rstrip()` 줄 끝의 줄바꿈 문자(`\n`)를 지웁니다.
- `if line == "": continue` 파일 끝에 빈 줄이 있으면 건너뜁니다.
- `line[1:]` 맨 앞 글자 `@`를 떼고 나머지만 리스트에 넣습니다.

결과 예: `['SRR1553607.1 1 length=101', 'SRR1553607.2 2 length=101', ...]`

> 서열과 품질 줄은 저장하지 않으므로, 큰 파일이어도 메모리를 적게 씁니다.

### 6-2. `base_name` — 기본 이름 만들기

```python
name = full_name.split()[0]
if name.endswith("/1") or name.endswith("/2"):
    name = name[:-2]
return name
```

- `split()`은 공백을 기준으로 문자열을 나눕니다. `[0]`은 첫 번째 덩어리(실제 ID)입니다.
  예: `'SRR1553607.1 1 length=101'.split()` → `['SRR1553607.1', '1', 'length=101']` → `'SRR1553607.1'`
- `endswith("/1")` 문자열이 `/1`로 끝나는지 검사합니다.
- `name[:-2]` 마지막 두 글자를 잘라냅니다. 예: `'read123/1'` → `'read123'`

### 6-3. `main` — 비교하고 결과 출력하기

**① 명령행 인자 확인**

```python
if len(sys.argv) != 3:
    print("사용법: python src/check_paired.py <read1.fastq> <read2.fastq>")
    sys.exit(1)
```

`sys.argv`는 실행할 때 입력한 단어들의 리스트입니다.
`python src/check_paired.py A.fastq B.fastq`라면 `sys.argv = ['src/check_paired.py', 'A.fastq', 'B.fastq']`로 길이가 3입니다.
파일을 두 개 주지 않으면 사용법을 알려 주고 종료합니다.

**② 두 파일 읽기와 개수 비교**

```python
names1 = read_fastq_names(file1)
names2 = read_fastq_names(file2)
is_paired = True
if count1 != count2:
    is_paired = False
    print(f"[개수 불일치] ...")
```

`is_paired`는 "지금까지 문제가 없었는가?"를 기억하는 변수입니다.
처음엔 `True`로 두고, 문제가 하나라도 발견되면 `False`로 바꿉니다.

**③ 같은 위치끼리 이름 비교 (핵심 반복문)**

```python
n_compare = min(count1, count2)
mismatch_count = 0

for i in range(n_compare):
    if base_name(names1[i]) != base_name(names2[i]):
        is_paired = False
        mismatch_count += 1
        print(f"[이름 불일치] {i + 1}번째 read: ...")
```

- 개수가 다를 수도 있으므로, **짧은 쪽 길이**(`min`)만큼만 1:1로 비교할 수 있습니다.
- `for i in range(n_compare):` i가 0, 1, 2, …, n_compare−1까지 바뀌며 반복합니다.
- 매번 R1의 i번째 이름과 R2의 i번째 이름을 `base_name`으로 다듬은 뒤 비교합니다.
- 다르면 불일치 개수를 1 늘리고, 몇 번째 read인지 출력합니다.
  (파이썬은 0부터 세지만 사람은 1부터 세므로 `i + 1`로 출력합니다.)

반복이 진행되는 모습:

| i | names1[i] | names2[i] | 기본 이름 비교 | 결과 |
|---|-----------|-----------|----------------|------|
| 0 | `SRR1553607.1 1 length=101` | `SRR1553607.1 1 length=101` | `SRR1553607.1` = `SRR1553607.1` | 일치 |
| 1 | `SRR1553607.2 2 length=101` | `SRR1553607.2 2 length=101` | `SRR1553607.2` = `SRR1553607.2` | 일치 |
| … | … | … | … | … |

**④ 짝 없는 read 출력**

```python
for i in range(n_compare, count1):
    print(f"[짝 없음] {i + 1}번째 read는 {file1}에만 있음: ...")
for i in range(n_compare, count2):
    print(f"[짝 없음] {i + 1}번째 read는 {file2}에만 있음: ...")
```

개수가 다르면 긴 쪽 파일 뒤에 짝 없는 read가 남습니다. 이 반복문들이 그 read를 출력합니다.
예를 들어 R1이 10개, R2가 8개면 `n_compare = 8`이고,
첫 번째 반복문은 i = 8, 9를 돌며 R1의 9·10번째 read를 출력합니다.
두 번째 반복문은 `range(8, 8)`이 비어 있으므로 한 번도 실행되지 않습니다.

**⑤ 최종 결과 출력**

두 파일의 read 개수, 이름 불일치 개수, 그리고 `is_paired`에 따라 `O` 또는 `X`를 출력합니다.

**⑥ `if __name__ == "__main__":`**

이 파일을 직접 실행했을 때만 `main()`을 호출합니다.
다른 파일에서 `import`해서 `base_name` 같은 함수만 가져다 쓸 때는 `main()`이 실행되지 않습니다.

```
사용법: python src/check_paired.py <read1.fastq> <read2.fastq>
```

### 결과 예시 1 — 짝이 맞는 경우 (실습 데이터의 실제 결과)

```
===== 결과 =====
data/SRR1553607_1.fastq read 개수: 203445
data/SRR1553607_2.fastq read 개수: 203445
이름 불일치 개수: 0
paired 여부: O (모든 read가 올바르게 짝을 이룹니다)
```

- 두 파일 모두 read가 **203,445개**로 같습니다.
- 같은 위치의 이름이 모두 같습니다(불일치 0).
- 따라서 이 두 파일은 그대로 paired-end 분석에 사용할 수 있습니다.

### 결과 예시 2 — 짝이 맞지 않는 경우 (가상의 예)

예를 들어 R1만 필터링해서 read 하나가 빠졌다면 다음처럼 나올 수 있습니다.

```
[개수 불일치] R1.fastq: 9개, R2.fastq: 10개
[이름 불일치] 3번째 read: 'SRR1553607.4 4 length=101'  vs  'SRR1553607.3 3 length=101'
[이름 불일치] 4번째 read: 'SRR1553607.5 5 length=101'  vs  'SRR1553607.4 4 length=101'
...
[짝 없음] 10번째 read는 R2.fastq에만 있음: 'SRR1553607.10 10 length=101'

===== 결과 =====
R1.fastq read 개수: 9
R2.fastq read 개수: 10
이름 불일치 개수: 7
paired 여부: X (짝이 맞지 않는 read가 있습니다)
```

### 출력 메시지 해석표

| 메시지 | 의미 | 확인할 것 |
|--------|------|-----------|
| `[개수 불일치]` | 두 파일의 read 수가 다름 | 한쪽만 trimming/필터링했는지, 파일이 잘렸는지 |
| `[이름 불일치] n번째 read` | 같은 위치의 read가 서로 다른 조각에서 옴 | **처음** 불일치가 나온 위치 근처에서 read가 빠졌을 가능성이 큼 |
| `[짝 없음]` | 한쪽 파일에만 남은 read | 개수 불일치의 결과로 생긴 나머지 read |
| `paired 여부: O` | 짝이 모두 맞음 | 그대로 분석 진행 가능 |
| `paired 여부: X` | 하나 이상 문제 있음 | 원본 파일을 다시 받거나, trimming을 R1·R2 **함께** 다시 수행 |

> **팁:** read 하나가 중간에 빠지면 그 뒤의 모든 read가 한 칸씩 밀리기 때문에,
> 불일치가 수천 개씩 출력될 수 있습니다. 이때는 **맨 처음 나온 불일치 위치**를 보는 것이 원인을 찾는 데 가장 도움이 됩니다.
>
> paired-end 데이터를 trimming할 때는 fastp처럼 R1과 R2를 **함께** 입력으로 받는 방식을 쓰면 짝이 깨지지 않습니다.
