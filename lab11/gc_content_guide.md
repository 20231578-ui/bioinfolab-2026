# gc_content.py 사용 설명서

> FASTQ 파일의 각 read에 대해 **GC 비율**과 **평균 품질 점수**를 계산하고,
> GC 비율이 아주 낮은 read와 아주 높은 read의 품질이 전체 평균과 어떻게 다른지 비교하는 프로그램입니다.
> 이 문서는 프로그래밍과 시퀀싱 데이터를 처음 접하는 사람도 따라올 수 있도록 작성했습니다.

---

## 1. 프로그램의 목적

시퀀싱 데이터에서는 **GC 비율이 극단적인 read(GC가 매우 높거나 매우 낮은 read)** 에서
품질이 나빠지거나 오류가 생기는 경우가 알려져 있습니다.
GC가 많은 서열은 구조가 단단해서 증폭(PCR)이나 시퀀싱 반응이 잘 안 될 수 있기 때문입니다.

`gc_content.py`는 다음 세 가지를 합니다.

1. **read마다** GC 비율(%)과 평균 품질 점수를 계산해 출력합니다.
2. **전체 read의 평균 품질**을 구합니다.
3. GC 비율이 **가장 낮은 10개 read**와 **가장 높은 10개 read**를 골라,
   각 그룹의 평균 품질이 전체 평균보다 얼마나 높거나 낮은지 보여 줍니다.

이를 통해 "이 데이터에서 GC 비율과 품질 사이에 관계가 있는가?"를 간단히 확인할 수 있습니다.

## 2. GC 비율의 의미와 계산 공식

DNA는 A, T, G, C 네 가지 염기로 이루어집니다.
**GC 비율(GC content)** 은 서열 중에서 G와 C가 차지하는 비율입니다.

```
GC 비율(%) = (G의 개수 + C의 개수) / 전체 염기 수 × 100
```

### 계산 예시

```
서열: A T G C G C A T G G   (10개)
G = 4개, C = 2개
GC 비율 = (4 + 2) / 10 × 100 = 60%
```

### 왜 중요할까?

- G–C 쌍은 수소 결합이 **3개**, A–T 쌍은 **2개**라서 GC가 많을수록 DNA 가닥이 더 단단히 붙어 있습니다.
- 생물 종마다 유전체의 평균 GC 비율이 대체로 정해져 있습니다(사람은 약 40% 정도).
- 그래서 GC 비율 분포를 보면 **오염(다른 생물의 DNA)** 이나 **시퀀싱 편향**을 의심해 볼 수 있습니다.

> 참고: 이 프로그램은 분모에 **N(판독 불가 염기)도 포함한 전체 길이**를 사용합니다.
> 따라서 N이 많은 read는 GC 비율이 실제보다 낮게 계산될 수 있습니다.

## 3. Phred 품질 점수의 계산 방법

### FASTQ의 구조

FASTQ 파일은 **read 하나가 항상 4줄**입니다.

```
@SRR1553607.1 1 length=101          ← 1번째 줄: '@' + read 이름
GTTAGCGTTGTTGATCGCGACGCAACAACTGG... ← 2번째 줄: 염기서열
+SRR1553607.1 1 length=101          ← 3번째 줄: '+' (구분용 줄)
BB@FFFFFHHHHHJJJJJJJJJJJJJJJJJJ... ← 4번째 줄: 품질 문자열 (염기 하나당 문자 하나)
```

### Phred 점수란?

Phred 품질 점수 Q는 그 염기가 **틀렸을 확률 P**를 나타냅니다.

```
Q = −10 × log₁₀(P)
```

| Q | 오류 확률 P | 정확도 |
|---|---|---|
| 10 | 1/10 | 90% |
| 20 | 1/100 | 99% |
| 30 | 1/1,000 | 99.9% |
| 40 | 1/10,000 | 99.99% |

점수가 **10 올라갈 때마다 오류 확률은 10분의 1**로 줄어듭니다.

### 문자를 점수로 바꾸기 (Phred+33)

FASTQ에는 점수를 숫자가 아니라 **"점수 + 33"에 해당하는 ASCII 문자**로 저장합니다.
따라서 문자의 ASCII 코드에서 33을 빼면 점수가 됩니다.

```
점수 = ord(문자) − 33
```

| 문자 | `ord(문자)` | 점수 |
|---|---|---|
| `#` | 35 | 2 |
| `5` | 53 | 20 |
| `?` | 63 | 30 |
| `I` | 73 | 40 |

### read의 평균 품질

read 하나의 평균 품질은 그 read의 모든 염기 점수의 평균입니다.

```
품질 문자열: I I ? #
점수:       40 40 30 2
평균 품질 = (40 + 40 + 30 + 2) / 4 = 28.0
```

## 4. 코드의 주요 부분 설명

```
GROUP_SIZE = 10    → 비교할 그룹 크기 (하위/상위 몇 개를 고를지)
read_fastq()       → FASTQ 파일을 읽어 read 목록을 만든다
gc_percent()       → 서열 하나의 GC 비율(%)을 계산한다
mean_quality()     → 품질 문자열 하나의 평균 점수를 계산한다
average()          → 숫자 리스트의 평균을 구한다
메인 실행 부분      → 계산 → 정렬 → 그룹 비교 → 출력
```

### 4-1. `read_fastq(filename)` — 파일 읽기

```python
for i in range(0, len(lines), 4):
    name = lines[i].rstrip()[1:]   # 맨 앞의 '@'를 떼어낸다.
    seq = lines[i + 1].rstrip()
    qual = lines[i + 3].rstrip()
    records.append((name, seq, qual))
```

- `range(0, len(lines), 4)`는 i를 0, 4, 8, … 처럼 **4씩 건너뛰게** 합니다. read 하나가 4줄이기 때문입니다.
- 결과는 `(이름, 서열, 품질문자열)` 튜플의 리스트입니다.

### 4-2. `gc_percent(seq)` — GC 비율

```python
if len(seq) == 0:
    return 0.0
seq = seq.upper()
gc_count = seq.count("G") + seq.count("C")
return gc_count / len(seq) * 100
```

- 길이가 0이면 0으로 나누는 오류가 생기므로 먼저 0.0을 돌려줍니다.
- `upper()`로 소문자(`g`, `c`)도 대문자로 바꿔서 함께 셉니다.
- `count("G")`는 문자열 안에서 `G`가 몇 번 나오는지 셉니다.

### 4-3. `mean_quality(qual)` — 평균 품질

```python
for ch in qual:
    scores.append(ord(ch) - 33)
return sum(scores) / len(scores)
```

- 품질 문자를 하나씩 꺼내 Phred 점수로 바꾼 뒤, 합계 ÷ 개수로 평균을 냅니다.

### 4-4. `average(values)` — 리스트의 평균

빈 리스트이면 0.0을, 아니면 `sum / len`을 돌려주는 작은 도우미 함수입니다.

### 4-5. 메인 실행 부분

**① read별 계산과 출력**

```python
for index, (name, seq, qual) in enumerate(reads):
    gc = gc_percent(seq)
    mq = mean_quality(qual)
    results.append((index, name, gc, mq))
    print(f"{name}\t{gc:.2f}\t{mq:.2f}")
```

- `enumerate`로 **파일에서의 순서 번호(index)** 도 함께 저장합니다. 이 번호는 정렬할 때 동점을 정리하는 데 씁니다.
- `results`의 각 항목은 `(순서번호, 이름, GC비율, 평균품질)` 입니다.
  즉 `r[0]`=순서번호, `r[1]`=이름, `r[2]`=GC비율, `r[3]`=평균품질.

**② 전체 평균 품질**

```python
all_quals = [mq for index, name, gc, mq in results]
overall_mean = average(all_quals)
```

- 각 read의 평균 품질을 다시 평균 냅니다. **read 하나를 한 표로** 취급하는 방식입니다.

**③ GC 비율로 정렬**

```python
sorted_low = sorted(results, key=lambda r: (r[2], r[0]))
sorted_high = sorted(results, key=lambda r: (-r[2], r[0]))
```

- `key`는 "무엇을 기준으로 정렬할지"를 정합니다.
- `sorted_low`: GC 비율이 **낮은 순**. GC가 같으면 파일에 먼저 나온 read가 앞.
- `sorted_high`: `-r[2]`처럼 음수로 바꾸면 GC 비율이 **높은 순**이 됩니다. 동점이면 역시 파일 순서.
- 동점 규칙을 정해 두었기 때문에 **몇 번을 실행해도 항상 같은 결과**가 나옵니다.

**④ 그룹 고르기와 평균**

```python
low_group = sorted_low[:GROUP_SIZE]
high_group = sorted_high[:GROUP_SIZE]
low_mean = average([r[3] for r in low_group])
high_mean = average([r[3] for r in high_group])
```

- `[:10]`은 앞에서부터 10개를 잘라 옵니다. read가 10개보다 적으면 있는 만큼만 가져오므로 오류가 나지 않습니다.

**⑤ 요약 출력**

- 전체 read 수와 전체 평균 품질을 출력합니다.
- read가 20개 미만이면 두 그룹에 같은 read가 겹칠 수 있다는 **주의 문구**를 출력합니다.
- 각 그룹의 read 목록과 그룹 평균, 그리고 **전체 대비 차이**(`+4.88`, `-14.68`처럼 부호 포함)를 출력합니다.

## 6. GC 비율이 높은 read와 낮은 read의 품질 비교 방법

### 비교 순서

1. **기준선 확인** — 먼저 `전체 평균 품질`(예시: 33.45)을 봅니다. 모든 비교의 기준입니다.
2. **그룹 평균 비교** — 각 그룹의 `평균 품질`과 괄호 안의 `전체 대비` 값을 봅니다.
   - `+` 이면 전체보다 품질이 좋고, `−` 이면 나쁩니다.
3. **그룹 안의 개별 read 확인** — 평균 하나만 보지 말고 10개 read의 값이 고르게 분포하는지 봅니다.

### 예시 데이터 해석

| 그룹 | GC 비율 범위 | 평균 품질 | 전체 대비 |
|---|---|---|---|
| GC 하위 10개 | 12.87 ~ 15.84% | 38.33 | **+4.88** |
| 전체 | — | 33.45 | 0 |
| GC 상위 10개 | 92.08 ~ 98.02% | 18.77 | **−14.68** |

- **GC가 매우 높은 read**는 품질이 크게 낮습니다. 평균 18.77로 Q20에도 못 미치며,
  개별 read 중에는 5.96, 9.06처럼 거의 신뢰할 수 없는 read도 있습니다.
  다만 32.28, 31.53처럼 품질이 괜찮은 read도 섞여 있어 그룹 안 편차가 큽니다.
- **GC가 매우 낮은 read**는 오히려 품질이 전체보다 높고, 값도 33~40으로 비교적 고릅니다.

GC 비율이 90%를 넘는 101bp read는 자연스러운 서열에서는 드뭅니다.
이런 read는 **실제 서열이라기보다 시퀀싱 오류나 인공 산물(artifact)일 가능성**을 의심해 볼 수 있습니다.
(예를 들어 일부 Illumina 기계에서는 신호가 약할 때 G로 읽히는 경향이 있습니다.)

### 더 확실하게 비교하려면

- 저장한 `gc_result.tsv`를 엑셀 등으로 열어 **GC 비율(x축) vs 평균 품질(y축) 산점도**를 그려 봅니다.
- `GROUP_SIZE`를 10에서 100이나 1000으로 바꿔 보며 결과가 비슷하게 유지되는지 확인합니다.
- trimming 후 파일(`data/trimmed.fastq`)에도 실행해서, 품질 낮은 고GC read가 줄었는지 비교합니다.
- FastQC 보고서의 *Per sequence GC content* 그래프와 함께 봅니다.

## 7. 결과 해석 시 주의사항

1. **10개는 아주 적은 표본입니다.** read 20만 개 중 양 끝 10개만 본 것이므로,
   "GC가 높을수록 품질이 낮다"는 일반적인 결론을 내리기에는 부족합니다. 극단값의 특징일 뿐일 수 있습니다.
2. **관계가 있어도 원인은 아닐 수 있습니다.** 고GC read의 품질이 낮은 것은
   "GC가 높아서 품질이 낮다"일 수도 있지만, 반대로 "품질이 낮아 오류가 생겨 G/C로 잘못 읽혔다"일 수도 있습니다.
3. **전체 평균 품질은 read 평균들의 평균입니다.** 이 데이터처럼 모든 read 길이가 같으면 염기 전체 평균과 같지만,
   trimming 후처럼 길이가 다르면 짧은 read와 긴 read가 같은 비중으로 계산되어 값이 조금 달라집니다.
4. **평균은 한 read 안의 나쁜 구간을 가립니다.** read 평균이 30이어도 끝부분 몇 염기는 Q2일 수 있습니다.
   위치별 품질은 `qual_by_position.py`로 따로 확인하세요.
5. **N 염기와 짧은 read에 주의하세요.** N은 GC 비율의 분모에 포함되므로 GC 비율이 낮게 나옵니다.
   또 길이가 짧은 read는 염기 몇 개만 바뀌어도 GC 비율이 크게 변해 극단 그룹에 들어가기 쉽습니다.
6. **read가 20개 미만이면 두 그룹이 겹칩니다.** 이때 프로그램이 주의 문구를 출력하니 결과를 그대로 믿지 마세요.
7. **Phred+33과 4줄 형식을 가정합니다.** 오래된 Phred+64 데이터나 서열이 여러 줄로 나뉜 FASTQ는 올바르게 처리하지 못합니다.
8. **파일 전체를 메모리에 올립니다.** 매우 큰 FASTQ 파일에서는 메모리가 부족할 수 있습니다.
